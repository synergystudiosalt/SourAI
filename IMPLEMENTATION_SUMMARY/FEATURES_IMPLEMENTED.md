# sour.ai - Three Independent Features Implementation

## Overview
Three major features have been implemented to enhance sour.ai with better code change visualization, stricter AI coding standards, and smarter agent autonomy.

---

## Feature 1: Edit Preview Component

### File Location
`src/components/EditPreview.tsx` (New)

### What It Does
Displays a visual summary of code changes generated by the agent in a Zed-style dark theme interface.

### Key Features
- **File Summary**: Shows count of files changed and line statistics (+added, -removed)
- **Expandable UI**: Smooth animation to collapse/expand the file list
- **Line Counts**: Each file shows color-coded line counts (green for additions, red for deletions)
- **Action Buttons**: 
  - "Keep All" button (Alt+Shift+Y) - accept all changes
  - "Reject All" button (Alt+Shift+Z) - reject all changes
- **Visual Design**: 
  - Gray-800 background for dark mode
  - Light text for contrast
  - Smooth Framer Motion animations
  - Hover states for interactivity

### Usage Example
```tsx
<EditPreview
  ops={fileOperations}
  isDarkMode={true}
  onRejectAll={() => handleReject()}
  onKeepAll={() => handleKeep()}
  messageId="msg-123"
/>
```

### Component Props
```typescript
interface EditPreviewProps {
  ops: AgentFileOp[];           // File operations to display
  isDarkMode: boolean;           // Theme preference
  onRejectAll: () => void;       // Callback for reject button
  onKeepAll: () => void;         // Callback for keep button
  messageId: string;             // ID for tracking
}
```

## Feature 2: Better AI Coding Instructions

### File Location
`functions/shared/systemPrompts.ts` (Updated)

### What It Does
Significantly enhances the system prompt to enforce production-ready code standards across all agent-generated code.

### Code Quality Standards Added

#### 1. **Type Safety**
- Explicit types for all function parameters and returns
- Proper interfaces/types instead of `any`
- Strict type checking in tsconfig.json
- Discriminated unions and type guards for complex logic

#### 2. **Error Handling & Validation**
- Try/catch blocks for async operations
- Input and API response validation
- Meaningful error messages with context
- Explicit edge case handling (null, undefined, empty arrays)
- No silent failures

#### 3. **Performance Optimization**
- Avoid N+1 query problems
- Cache expensive computations (memoization)
- Debounce/throttle frequent calls
- Lazy loading for large datasets
- Bundle size optimization with tree-shaking
- Profile before claiming optimizations

#### 4. **Security Best Practices**
- Never hardcode secrets or API keys
- Environment variables for sensitive data
- Input sanitization against injection attacks
- HTTPS-only for API calls
- Rate limiting for public APIs
- OWASP guidelines compliance

#### 5. **Testing Approach**
- Unit tests for business logic functions
- Integration tests for complex workflows
- Error cases and edge conditions tested
- >80% code coverage on critical paths
- Descriptive test names documenting intent
- Proper external dependency mocking

#### 6. **Documentation & Comments**
- JSDoc/TSDoc for public APIs
- Parameter descriptions and type info
- Examples in documentation
- DRY comments (no code repetition)
- Constraint and assumption documentation
- README updates for new features

#### 7. **Code Organization (DRY Principle)**
- Extract repeated logic into functions
- Group related functionality
- Consistent naming conventions
- Single responsibility per file
- Avoid circular dependencies
- Barrel exports for clean imports

#### 8. **Accessibility (WCAG AA)**
- Semantic HTML (button, nav, main, etc.)
- Alt text for all images
- Color contrast 4.5:1 for normal text
- Keyboard navigation (Tab, Enter, Escape)
- ARIA labels for complex components
- Screen reader testing

#### 9. **Environmental & Configuration**
- Multiple environment support (dev, staging, prod)
- .env files for environment-specific config
- Never commit secrets to .gitignore
- Document required environment variables
- Provide .env.example file
- Log important events for debugging

#### 10. **Automatic Improvement Suggestions**
- Proactively suggest tests for new functions
- Detect and suggest refactoring opportunities
- Flag security issues immediately
- Recommend performance fixes when apparent
- Add documentation without asking

## Feature 3: Subagent Image Upload & Smart Functions

### File Location
`src/components/workspace/AgentPanel.tsx` (Updated)

### What It Does
Enables the subagent input to accept image uploads and automatically invoke agent functions based on user intent, making the agent more autonomous and intelligent.

### Sub-Features

#### A. Image Upload Support
- **Image Button**: New image icon button in the subagent input toolbar
- **Attachment Popover**: Reuses existing `AttachmentPopover` component
- **Integration**: Images can be attached to subagent messages for visual context
- **Positioning**: Popover positioned above input area for easy access

#### B. Smart Function Auto-Detection
Auto-calls agent functions based on user language patterns:

**Pattern 1: Read/View Operations**
- Keywords: "read", "view", "show", "open", "check", "display", "cat"
- Automatically calls: `@@readfile`
- Example: "read src/App.tsx" → auto-calls `@@readfile: src/App.tsx`

**Pattern 2: Search/Find Operations**
- Keywords: "search", "find", "locate", "grep", "look for", "where", "detect"
- Automatically calls: `@@findall`
- Example: "find all imports" → auto-calls `@@findall: import`

**Implementation Details:**

```typescript
  // Returns { promptToSend: string, autoCalledFunctions: string[] }
  // Appends @@ directives when patterns match

```

#### C. Complex Task Subagent Detection
Automatically detects when a task is complex enough to warrant subagent delegation:

**Triggers:**
- Word count > 60 AND sentence count ≥ 2
- Multiple topics (AND, also, plus, additionally, furthermore) AND sentence count ≥ 2

**Behavior:**
- Spawns subagents for parallel work on independent subtasks
- Displays notification: "_[Complex task detected — spawning subagents for parallel work]_"

#### D. Auto-Called Functions Notification
When functions are auto-called, the UI displays:
```
_[Auto-called: @@readfile, @@findall]_
```

This shows the user exactly what the agent did autonomously.

#### E. Subagent Image Attachment Passing
Subagents can receive and pass image attachments to the parent agent for visual context analysis.

### Code Changes Summary

**New State:**
- `showAttachmentPopover`: Boolean to toggle image upload menu
- `attachmentPopoverRef`: Reference for click-outside detection

**New Functions:**
- `autoDetectAndCallFunctions()`: Detects action words and injects @@ calls
- `shouldAutoSpawnSubagents()`: Analyzes task complexity for delegation

**New Effects:**
- Click-outside handler for attachment popover closure

**Modified Functions:**
- `handleSend()`: Integrated smart function detection and subagent triggering
- Input area: Added image upload button

### User Experience Flow

1. **User types command** with action words (read, search, find, etc.)
2. **Agent analyzes input** before sending
3. **Functions auto-called** if patterns match (user sees this in chat)
4. **Complex tasks detected** and split into parallel subagents
5. **Images can be attached** for visual context
6. **Results shown** with clear indication of autonomous actions

### Keyboard Shortcuts
- `Alt+Shift+Z`: Reject all edits (from EditPreview)
- `Alt+Shift+Y`: Accept all edits (from EditPreview)
